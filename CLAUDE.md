# 6d7 (D&D VTT) — виртуальный стол для D&D 2024

Рабочее название приложения — **6d7**; архив кампании — `.6d7`.

Главный проект (с 31.10.2026): веб-приложение на React для игры в D&D онлайн — главный экран, редактор кампании (мастер), игра игрока и игра мастера с разным функционалом, клиент-серверная архитектура (сервер ещё не проектировали). Код — в `vtt/`. Старое приложение-лист (`app/`, сайт https://nkognit0.github.io/dnd-app/) «живёт своей жизнью»; его лист нужен VTT только как компонент.

Отвечать по-русски, пользователь — мужчина (мужской род). История решений — в памяти этого проекта.

## Как работать

- Делать только то, что попросили, по шагам. Если пользователь просит «только задавай вопросы» или «пока ничего не делай» — ничего не менять, только спрашивать.
- Вопросы задавать нумерованным списком, сгруппированным по темам; то, что можно решить самому, писать отдельным списком «допущения» — пользователь поправит.
- Коммит и пуш — только по явной просьбе. Коммиты только так: `git -c user.name=nkognit0 -c user.email=85009858+nkognit0@users.noreply.github.com commit …`. Глобальный git config не менять.
- VTT — локальный git в корне проекта (ветка `main`; в нём `vtt/`, `docs/`, `assets/`, этот файл, `.claude/launch.json`; `app/`, `dnd-sheet/`, `dnd-db/`, `design-preview/` исключены в `.gitignore`). Удалённого репозитория ещё нет: **приватный** репозиторий на GitHub создаёт пользователь. Концы строк — LF (`.gitattributes`).
- Не публиковать `dnd-db/raw` и личные данные. Не вводить пароли.
- Неотслеживаемые файлы в `app/` (лист `preview/`, токены `public/tokens/`) не удалять.

## Критерии всех технических решений

1. Минимальная задержка между игроками.
2. Ресурсы с открытой лицензией. **Пока проект приватный**, контент правил из закрытых источников (PHB, FotA и др.) использовать можно; к публичному релизу его отделить.
3. Весь процесс игры **игрока** работает с телефона и планшета (стек кроссплатформенный). Мастер (редактор и игра мастера) работает с ПК; построение карт — только ПК.

Позже — публичная бесплатная версия с открытым кодом.

## План разработки

Интерфейс делается раньше сервера:
1. Атомарные компоненты по дизайн-системе — **сделано** (`vtt/src/ui`).
2. Страница-превью всех компонентов для проверки пользователем — **сделано** (`vtt/src/preview`, адрес `#preview`).
3. Экраны на этой библиотеке для локальной проверки: главное меню, редактор, игра игрока, игра мастера — **следующий шаг**. Сюда же: лист персонажа (утверждённый лист из `app/preview/` в тёмной теме), лист спутника (по правилам, в дизайне листа), визарды (старая структура, стили макета) и новые визарды спутника, канвас карты. Прототип карты — **сделан, ждёт проверки** (`vtt/src/map`, страница `#map`). Листы персонажа и спутника, инвентари предметов и заклинаний на новой модели данных — **сделаны, ждут проверки** (`vtt/src/game`, страница `#sheet`).

Дальше — офлайн-версия всего приложения по этапам `docs/dev-plan.md` (план от 03.11.2026, ответы пользователя — в QnA). Этапы 1 (каркас и данные кампании) и 2 (главный экран, `src/home/`) сделаны и закоммичены 03.11.2026; этап 3 (оболочка редактора, «Игроки», «Параметры», `src/editor/`) закоммичен; этап 4 (редактор карт, `src/editor/maps/`) сделан и ждёт проверки; следующий — этап 5 (каталог NPC).

Каждый шаг — после проверки предыдущего пользователем.

## VTT: устройство и правила кода (`vtt/`)

Vite 5 + React 18 + TypeScript, CSS Modules, **без UI-кита**. Шрифты: Inter (`@fontsource/inter` 400/500/600/700) и PT Serif Caption для листа персонажа (`@fontsource/pt-serif-caption` 400, OFL). Только тёмная тема.

- `src/ui/tokens/colors.css` — генерируется `npm run tokens` из `assets/dnd-tokens-dark.json` (`txt/primary` → `--txt-primary`; deprecated пропускаются). Руками не править.
- `src/ui/tokens/foundation.css` — отступы `--spacer-*`, скругления `--radius-*`, тени `--elevation-*`, оверлей, стили текста `--font-*` (body, title, display, navigation, multiline, caption, caption-strong, caption-bold, result) и **стили листа персонажа** `--font-sheet-*` (label, caption, hint, value, number, text; засечки — `--font-family-serif`), `--letter-spacing-sheet-title`, линии полей `--sheet-rule` / `--sheet-rule-active`. Классы для экранов — `src/ui/tokens/text.module.css` (`sheetTitle`, `sheetHeading`, `sheetLabel`, `sheetCaption`, `sheetHint`, `sheetValue`, `sheetValueUpper`, `sheetNumber`, `sheetText`, `sheetMuted`; в них зашит и цвет). Лист и всё в его стиле (лист спутника) собирать только из них.
- `src/ui/icons/` — `npm run icons` копирует `assets/icon.*` в `svg/`: одноцветные (`icon.16`, `icon.28`) получают `currentColor`; цветные и иконки игроков — как есть, с файлом `geometry.json` (тени зашиты в SVG: рисунок + 8 px слева/справа, 10 сверху, 6 снизу). Компоненты: `Icon`, `Icon28`, `ColorIcon`, `PlayerIcon`, `PlayerIcon42`.
- `src/ui/scrollbar.css` — скроллбар дизайн-системы для всего приложения (`::-webkit-scrollbar`). В компонентах не задавать `scrollbar-color`/`scrollbar-width`: в Chromium они отключают эти правила.
- `src/ui/components/*` — компоненты, экспорт в `src/ui/index.ts`; список с id Figma — `docs/ui-catalog.md`.
- `src/app/` — корень: адреса экранов после `#` (`route.ts`: `#/` главный экран, `#/c/<id>/maps|npc|players|settings` редактор, `#/c/<id>/play` игра мастера, `#/join/<код>` игра игрока; страницы разработки `#preview[/<компонент>]`, `#map`, `#sheet`), горячие клавиши (`shortcuts.ts`: одна таблица команд `COMMANDS`, один обработчик, `useShortcuts(область, обработчики)`, подсказки меню — `shortcutLabel`; клавиши по `KeyboardEvent.code`, чтобы работали в русской раскладке; в текстовых полях не срабатывают). Экраны следующих этапов пока — заглушки.
- `src/campaign/` — кампании (модель — `docs/data-model.md`), снаружи — только `index.ts`. Документы и операции (`types.ts`, `campaign.ts`), открытая кампания `CampaignSession` (`session.ts`: правки `apply(changes)`, журнал и снимки — автосохранение, «Отменить / Повторить» — `history.ts`; карта меняет свой `MapStore` сама, сессия слушает его), хранилище браузера `repo` (`local/LocalRepo.ts`, IndexedDB `vtt-campaigns`: документы, журнал, сводки, тайлы, коды), архив `.6d7` (`archive.ts` — упаковка без браузера, `local/transfer.ts` — экспорт и импорт), хук `useSession`. Без React, кроме хука: пойдёт на сервер.
- `src/home/` — главный экран: `HomeScreen` (кампании этого браузера плитками, «Создать», импорт `.6d7`), `CampaignTile` (правый щелчок — «Переименовать», «Удалить»), `JoinDialog` (окно кода; код ищется среди игроков кампаний этого браузера, игра открывается в новой вкладке).
- `src/editor/` — редактор кампании: `EditorScreen` (открывает кампанию `useSession`; меню кампании — отменить, повторить, сохранить, экспорт, импорт в эту кампанию (`importInto`, отменяется), переименовать, выйти, удалить (`session.discard()`, потом `repo.remove`); переключатель режимов только на «Картах»; Ctrl+Z / Ctrl+Shift+Z через `useShortcuts('editor')`), вкладки `PlayersTab`, `SettingsTab` на общем `TabPage`; «NPC» — заглушка этапа 5.
- `src/editor/maps/` — редактор карт: `MapsTab` (открытая карта — в адресе; карта меняется через `session.apply` или прямо через `MapStore` движком — сессия слушает и то и другое), `MapList`, `MapPanel` (картинка режется в `repo.tiles`, файл и превью — в хранилище медиа; условия карты — переопределения настроек кампании), `NpcDialog`. Движок получает `look: 'player'` в режиме «Глазами игрока».
- `src/npc/catalog.ts` — каталог токенов NPC (210, из `app/src/tokens/tokens.json`), поиск по виду и редкости на русском и английском (`matches`, `searchTokens`).
- `src/preview/` — страница-превью: у каждого компонента все состояния и «живой пример». Новый компонент сразу добавлять на превью.
- `src/map/` — интерактивная карта на PixiJS 8 (WebGL2), снаружи — только `src/map/index.ts`. `core/` — данные карты без браузера (этот же код пойдёт на сервер): `MapScene`, операции `MapOp` и `MapStore` (через них идут все изменения, потом — и сеть), `Pin` (привязанное к сетке — в клетках, свободное — в пикселях картинки), видимость и проходимость. `image/` — загрузка PNG/JPEG/WebP/AVIF и пирамида тайлов 512 px в воркерах (кодирование — пулом `tile.worker`), тестовое подземелье. `engine/` — `MapEngine`: камера (100% = клетка 128 px), слои (тайлы, сетка-шейдер, постройки, фишки, рисунки, туман-маски), жесты и инструменты; цвета — только из токенов (`engine/theme.ts`); кадр рисуется только при изменениях. `react/` — `MapView`, `useMapScene`. Шкала сетки 1–10 → пиксели — `PX_PER_GRID_UNIT` в `core/geometry.ts` (пока 1 = 50 px). Прототип с панелью и счётчиками скорости — `src/preview/map/`, открывается по `#map`.

- `src/game/` — то, что хранит и показывает игрок (модель — `docs/data-model.md`). `seat/seat.ts` — лист игрока `Seat` (свободные поля листа, заклинания по id, 72 ячейки предметов без слотов героя, лист спутника) и переходники к логике старого приложения (`characterOf`, `withCharacter`); `seat/actions.ts` — действия с предметами, заклинаниями и ячейками; `seat/import.ts` — импорт листа старого приложения. `media/media.ts` — хранилище файлов по SHA-256 (IndexedDB, потом сервер); картинки листа уменьшаются до 512 px в WebP, поле хранит `media:<хэш>`. `sheet/` — листы персонажа и спутника, `inventory/` — окна инвентарей. Демо — `src/preview/sheet/`, страница `#sheet` (персонаж `demo-character.json` создан логикой `app/` и проходит импорт).
- Логика правил и база берутся на месте: псевдонимы `@app` → `app/src`, `@data` → `dnd-db/data`; `dnd-sheet` — прокладка `src/game/dndSheet.ts` (тип листа и подписи, без компонентов и Bootstrap). Иконки предметов и заклинаний и токены NPC dev-сервер отдаёт из `app/public/icons` и `app/public/tokens` (в сборку `npm run build` они пока не попадают). При создании репозитория VTT логику вынести в общий пакет.

Правила:
- Только токены: цвета, отступы, скругления, тени, `font: var(--font-*)`. Никаких «магических» значений, кроме размеров из макета.
- Стили текста — `font: var(--font-*)` прямо в стилях компонента; **не** `composes` из `text.module.css` (в dev порядок CSS-модулей ломал жирность).
- **Никаких плавных переходов и анимаций** между состояниями — состояния меняются мгновенно (`transition`/`animation` не писать).
- Состояния (hover, active, focus, disabled) — из браузера; проп `previewState` + `data-state` закрепляют их на превью.
- Обводки и фокус — `box-shadow: inset …`, без сдвига размеров.
- Тексты интерфейса — только из каталога `src/i18n/` (`useStrings()`; язык меняется одной настройкой, как variables в Figma); пока только русский. Новый текст сначала добавить в `ru.ts`.
- Цвет игрока — один из 8 `flow/*` (red, orange, yellow, green, blue, indigo, purple, scarlett); у мастера в иконках серый.
- После правок: `npx tsc --noEmit` и `npm test` (vitest: логика карты, кампании, архива, каталога NPC); смотреть результат на превью.

## База правил (`dnd-db/`)

- Сборка: `perl scripts/extract_official.pl && perl scripts/extract_wikidot.pl && perl scripts/extract_dndsu.pl && perl scripts/extract_bestiary.pl && perl scripts/extract_magic_items.pl && perl scripts/build.pl && perl scripts/validate.pl` (обычно хватает `build.pl` + `validate.pl`). Расхождения источников — `build/report.txt`. Ручные данные — `sources/curated/`.
- Магические предметы — `data/magic-items.json` (Open5e SRD 2024, группировка `scripts/extract_magic_items.pl`, ручное — `sources/curated/magic-items.json`); у всех предметов `requires_attunement` и `light`. Русские описания для визардов — `description_ru` (`sources/curated/descriptions-ru/`), восстановление ресурсов — `uses` (`sources/curated/uses.json`), мультикласс и лимит настройки — в `rules.json`.
- Спутники: `data/companions.json` (виды, кто их даёт — `access`, рост с уровнем, правила своими словами, возврат после 0 хитов — `revive`: `recast` / `slot` / `none`), `data/creatures.json` (101 блок статистики), `data/creature-types.json`. Ручные данные — `sources/curated/companions.json`; формулы с переменными `level`, `slot`, `pb`, `str…cha`, `spell_attack`, `spell_dc` (деление округляется вниз, есть `max`/`min`).
- Дикий облик: правила — `sources/curated/wild-shape.json` → `rules.wild_shape` (таблица обликов, Облики Круга луны); облики — все звери SRD до опасности 6 в `creatures.json` с `wild_shape: true` (88, без гигантской мухи — её нет на dnd.su).
- Выборы «Нового уровня» — `sources/curated/level-up.json`: выборы классов и подклассов, группы вариантов `class_options` (в т.ч. `land-type` с заклинаниями местности, `hunters-prey`, `defensive-tactics`, `armor-model`); `swap_on_rest: short|long` — вариант меняется на отдыхе.
- Русские описания своими словами — `sources/curated/descriptions-ru/*.json` (секция = цель overlay): умения классов (`class-features.json`, 188) и подклассов (`subclass-features.json`, ключ `подкласс/умение`, 274), варианты, существа и др. Ручные правила: `attunement.json`, `multiclass.json`, `uses.json`, `wild-shape.json`.
- Страницы next.dnd.su качать `sh scripts/fetch_dndsu.sh <папка> <путь>…` (через r.jina.ai; сам dnd.su с машины не открывается). Ссылки бестиария — из JSON внутри страницы `/bestiary/` (поле `link`). Существа SRD сверяются с Open5e (у него все Tiny записаны Small). На dnd.su «Лежащий ничком» — «Опрокинутый», рой — «рой крошечных Зверей».
- **`dnd-db/data` целиком копируется в публичный репозиторий старого листа** (`npm run vendor` в `app/`), поэтому в `data/` — только механика, названия и тексты SRD; не-SRD — пересказ своими словами (`summary_ru`).

## Подводные камни

- В heredoc Git Bash портятся обратные слэши и обратные кавычки — скрипты и JSON со списками замен писать в файлы (Write). В `node -e "…"` обратные кавычки оболочка исполняет как команды.
- Автоматический режим не даёт писать в `localStorage` страницы и подтверждать очистку листа: тестовые данные вводить через интерфейс. Хранилище панели браузера сбрасывается, когда панель закрывается.
- `npm run icons` пересоздаёт `src/ui/icons/svg` — запущенный Vite ловит ошибку импорта `geometry.json`; после скрипта перезагрузить страницу.
- Файловый наблюдатель Vite иногда пропускает правки — `touch` файла помогает.
- Часть файлов `dnd-sheet` в CRLF: правки точным совпадением строк ломаются.
- Рабочая папка PowerShell внутри папки не даёт её переместить.
- Когда окно приложения за другими окнами, снимок экрана в панели браузера не получается («page did not finish rendering») — проверять через DOM и вычисленные стили.
- Пока панель браузера скрыта, `requestAnimationFrame` не срабатывает и карта не перерисовывается (скриншоты устаревают). Для проверок подменить в странице: `window.requestAnimationFrame = (cb) => setTimeout(() => cb(performance.now()), 16)`.
- Переход `navigate` на тот же адрес с `#map` страницу не перезагружает — состояние остаётся; нужен `location.reload()`.
- В своих шейдерах PixiJS не называть uniform `uColor`, `uTransformMatrix`, `uRound`, `uProjectionMatrix`, `uWorldTransformMatrix`, `uResolution`: Pixi подставляет под этими именами свои значения (из-за `uColor` сетка была белой).
- Модули для проверок в браузере грузить `await import('/src/…')`. Первый импорт новой зависимости (как `fflate`) заставляет Vite пересобрать зависимости и перезагрузить страницу — скрипт обрывается; запустить его ещё раз. Проверочные кампании потом удалить (`repo.remove`).
- В Git Bash не писать `cat > файл` без heredoc: команда ждёт ввода и висит до таймаута.
